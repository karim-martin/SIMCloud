Linked Lists

A chain of nodes, where each node knows only the next one. Cheap to insert, expensive to search.

Linked list in one sentence

Instead of one block of memory with numbered slots, a linked list is a chain: each item is a small object (a node) holding a value and a reference to the next node. Like a treasure hunt where each clue points to the next one.

The shape

Singly linked list: head -> 10 -> 20 -> 30 -> null
head
reference
→
10
Next →
→
20
Next →
→
30
Next = null

The nodes can sit anywhere in memory. Nothing is contiguous, so there is no index arithmetic: to reach the fifth item you must start at the head and follow four references.

The node

The whole idea is one class that points at another instance of itself:

public class Node<T>
{
    public T Value { get; set; }
    public Node<T>? Next { get; set; }      // null marks the end of the chain

    public Node(T value) => Value = value;
}
// Build a chain by hand to see the mechanics
var first  = new Node<int>(10);
var second = new Node<int>(20);
var third  = new Node<int>(30);

first.Next = second;
second.Next = third;                        // third.Next stays null

// Walk it
Node<int>? current = first;
while (current is not null)
{
    Console.Write(current.Value + " -> ");
    current = current.Next;
}
Console.WriteLine("null");                  // 10 -> 20 -> 30 -> null

A singly linked list, from scratch

public class MyLinkedList<T>
{
    private Node<T>? _head;
    private Node<T>? _tail;      // keeping a tail reference makes AddLast O(1)

    public int Count { get; private set; }

    // O(1) - the new node becomes the head
    public void AddFirst(T value)
    {
        var node = new Node<T>(value) { Next = _head };
        _head = node;
        _tail ??= node;          // first item is also the tail
        Count++;
    }

    // O(1) thanks to the tail reference; O(n) without one
    public void AddLast(T value)
    {
        var node = new Node<T>(value);
        if (_tail is null)
        {
            _head = _tail = node;
        }
        else
        {
            _tail.Next = node;
            _tail = node;
        }
        Count++;
    }

    // O(n) - no shortcut, we must walk the chain
    public bool Contains(T value)
    {
        for (Node<T>? current = _head; current is not null; current = current.Next)
            if (EqualityComparer<T>.Default.Equals(current.Value, value))
                return true;
        return false;
    }

    // O(n) to find it, but the removal itself is just one reference change
    public bool Remove(T value)
    {
        Node<T>? previous = null;
        Node<T>? current = _head;

        while (current is not null)
        {
            if (EqualityComparer<T>.Default.Equals(current.Value, value))
            {
                if (previous is null) _head = current.Next;   // removing the head
                else previous.Next = current.Next;            // skip over current

                if (ReferenceEquals(current, _tail)) _tail = previous;
                Count--;
                return true;
            }

            previous = current;
            current = current.Next;
        }
        return false;
    }

    // O(n) - reverse the direction of every link
    public void Reverse()
    {
        Node<T>? previous = null;
        Node<T>? current = _head;
        _tail = _head;

        while (current is not null)
        {
            Node<T>? next = current.Next;   // remember where we were going
            current.Next = previous;        // flip the link backwards
            previous = current;             // step forward
            current = next;
        }
        _head = previous;
    }

    public override string ToString()
    {
        var sb = new StringBuilder();
        for (Node<T>? c = _head; c is not null; c = c.Next)
            sb.Append(c.Value).Append(" -> ");
        return sb.Append("null").ToString();
    }
}
var list = new MyLinkedList<int>();
list.AddLast(10);
list.AddLast(20);
list.AddLast(30);
list.AddFirst(5);

Console.WriteLine(list);              // 5 -> 10 -> 20 -> 30 -> null
Console.WriteLine(list.Contains(20)); // True

list.Remove(20);
Console.WriteLine(list);              // 5 -> 10 -> 30 -> null

list.Reverse();
Console.WriteLine(list);              // 30 -> 10 -> 5 -> null
Console.WriteLine(list.Count);        // 3
The insight worth keeping

Inserting or removing in the middle of an array means shifting every element after it. In a linked list it is two assignments - no matter how long the list is. The catch is that getting to the middle takes O(n) steps in the first place.

Doubly linked lists

Add a Previous reference and the chain can be walked in both directions, and any node can be removed in O(1) without knowing what came before it.

public class DoublyNode<T>
{
    public T Value { get; set; }
    public DoublyNode<T>? Next { get; set; }
    public DoublyNode<T>? Previous { get; set; }

    public DoublyNode(T value) => Value = value;
}

// Removing a node you already hold - O(1), no traversal at all
void RemoveNode<T>(DoublyNode<T> node)
{
    if (node.Previous is not null) node.Previous.Next = node.Next;
    if (node.Next is not null)     node.Next.Previous = node.Previous;
    node.Next = node.Previous = null;
}

.NET already has one: LinkedList<T>

var list = new LinkedList<string>();

LinkedListNode<string> b = list.AddLast("B");
list.AddFirst("A");
list.AddLast("D");
list.AddAfter(b, "C");                        // O(1) - we hold the node

Console.WriteLine(string.Join(" ", list));    // A B C D
Console.WriteLine(list.First!.Value);         // A
Console.WriteLine(list.Last!.Value);          // D

list.Remove(b);                               // O(1) - node known
Console.WriteLine(string.Join(" ", list));    // A C D

LinkedListNode<string>? found = list.Find("C");  // O(n) - has to search
if (found is not null) list.AddBefore(found, "B2");

// Walk backwards - only possible because it is doubly linked
for (var node = list.Last; node is not null; node = node.Previous)
    Console.Write(node.Value + " ");          // D C B2 A

Array vs linked list

OperationArray / List<T>LinkedList<T>Winner
Access by indexO(1)O(n)Array
Add at endO(1) amortisedO(1)Tie
Add at startO(n)O(1)Linked list
Insert/remove given the positionO(n) - shiftingO(1) - given the nodeLinked list
Search by valueO(n)O(n)Tie on paper, array in practice
Memory per itemJust the valueValue + 1-2 references + object headerArray
Cache friendlinessExcellent - contiguousPoor - nodes scatteredArray
In practice, reach for List<T> first

Textbooks make linked lists sound like the fast choice for insertion. On real hardware, contiguous memory is so much friendlier to the CPU cache that List<T> usually wins even where the Big-O says otherwise. Use LinkedList<T> when you are constantly adding and removing at both ends, and you already hold references to the nodes involved.

UseWhy a linked list fits

Two classic exercises

Both come up constantly in interviews, and both are worth understanding because they show the technique of using two references moving at different speeds.

// Find the middle node in ONE pass:
// slow moves 1 step, fast moves 2 - when fast hits the end, slow is halfway.
Node<T>? FindMiddle<T>(Node<T>? head)
{
    Node<T>? slow = head, fast = head;
    while (fast?.Next is not null)
    {
        slow = slow!.Next;
        fast = fast.Next.Next;
    }
    return slow;
}

// Detect a cycle (a node whose Next eventually points backwards).
// If there is a loop, the fast pointer laps the slow one and they meet.
bool HasCycle<T>(Node<T>? head)
{
    Node<T>? slow = head, fast = head;
    while (fast?.Next is not null)
    {
        slow = slow!.Next;
        fast = fast.Next.Next;
        if (ReferenceEquals(slow, fast)) return true;
    }
    return false;                       // reached null: no cycle
}
