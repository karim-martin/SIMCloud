Stacks & Queues

Two structures defined by one rule each: which item are you allowed to take out next?

Two everyday analogies

A stack is a pile of plates: you add to the top and take from the top, so the last plate on is the first one off (LIFO). A queue is a line at a coffee shop: you join at the back and are served from the front, so the first person in is the first one out (FIFO).

Stack - last in, first out

Push 1, 2, 3 then Pop
3
top - Pop() returns this
2
1
bottom - pushed first, leaves last
var stack = new Stack<string>();

stack.Push("page1");            // O(1)
stack.Push("page2");
stack.Push("page3");

Console.WriteLine(stack.Peek());   // page3   - look without removing
Console.WriteLine(stack.Pop());    // page3   - remove and return  O(1)
Console.WriteLine(stack.Pop());    // page2
Console.WriteLine(stack.Count);    // 1

// Always check before popping an empty stack - Pop() throws
if (stack.TryPop(out string? top))
    Console.WriteLine(top);        // page1

Console.WriteLine(stack.Count);    // 0
// stack.Pop();                    // InvalidOperationException

Building a stack from scratch

public class MyStack<T>
{
    private T[] _items = new T[4];
    private int _count;

    public int Count => _count;
    public bool IsEmpty => _count == 0;

    public void Push(T item)
    {
        if (_count == _items.Length)
            Array.Resize(ref _items, _items.Length * 2);
        _items[_count++] = item;                 // write at the top, move up
    }

    public T Pop()
    {
        if (IsEmpty) throw new InvalidOperationException("Stack is empty.");
        T item = _items[--_count];               // move down, read the top
        _items[_count] = default!;               // let the GC reclaim it
        return item;
    }

    public T Peek()
    {
        if (IsEmpty) throw new InvalidOperationException("Stack is empty.");
        return _items[_count - 1];
    }
}

Every operation touches only the end of the array, so nothing ever shifts. That is why all three are O(1).

What stacks are used for

UseWhy LIFO fits
The call stackThe most recently called method must finish and return first
Undo / redoUndo reverses the most recent action
Browser back buttonBack goes to the page you visited most recently
Bracket and tag matchingThe most recently opened bracket must close first
Depth-first searchExplore the newest branch fully before backtracking
Expression evaluationOperators and operands are consumed most-recent-first

Worked example: balanced brackets

The classic stack problem, and a genuinely useful one - it is how editors highlight mismatched brackets.

bool IsBalanced(string input)
{
    var pairs = new Dictionary<char, char>
    {
        [')'] = '(',
        [']'] = '[',
        ['}'] = '{'
    };

    var stack = new Stack<char>();

    foreach (char c in input)
    {
        if (c is '(' or '[' or '{')
        {
            stack.Push(c);                      // remember what was opened
        }
        else if (pairs.ContainsKey(c))
        {
            // A closer must match the most recently opened bracket
            if (stack.Count == 0 || stack.Pop() != pairs[c])
                return false;
        }
    }

    return stack.Count == 0;                    // nothing left unclosed
}

Console.WriteLine(IsBalanced("{[()]}"));        // True
Console.WriteLine(IsBalanced("{[(])}"));        // False - wrong closing order
Console.WriteLine(IsBalanced("(()"));           // False - one left open

Worked example: undo

public class TextEditor
{
    private string _text = "";
    private readonly Stack<string> _undo = new();
    private readonly Stack<string> _redo = new();

    public string Text => _text;

    public void Type(string addition)
    {
        _undo.Push(_text);        // snapshot the state BEFORE the change
        _redo.Clear();            // a new edit invalidates the redo history
        _text += addition;
    }

    public void Undo()
    {
        if (_undo.Count == 0) return;
        _redo.Push(_text);
        _text = _undo.Pop();
    }

    public void Redo()
    {
        if (_redo.Count == 0) return;
        _undo.Push(_text);
        _text = _redo.Pop();
    }
}

var editor = new TextEditor();
editor.Type("Hello");
editor.Type(", world");
Console.WriteLine(editor.Text);   // Hello, world
editor.Undo();
Console.WriteLine(editor.Text);   // Hello
editor.Redo();
Console.WriteLine(editor.Text);   // Hello, world

Queue - first in, first out

Enqueue A, B, C then Dequeue
A
front - Dequeue() returns this
→
B
→
C
back - joined last
var queue = new Queue<string>();

queue.Enqueue("job1");             // join the back    O(1)
queue.Enqueue("job2");
queue.Enqueue("job3");

Console.WriteLine(queue.Peek());     // job1  - who is next, without serving them
Console.WriteLine(queue.Dequeue());  // job1  - serve the front   O(1)
Console.WriteLine(queue.Dequeue());  // job2
Console.WriteLine(queue.Count);      // 1

if (queue.TryDequeue(out string? next))
    Console.WriteLine(next);         // job3
// queue.Dequeue();                  // InvalidOperationException on empty

What queues are used for

UseWhy FIFO fits
Background job processingWork is handled in the order it arrived - fairness
Print spoolingFirst document submitted prints first
Request buffering / rate limitingAbsorb bursts without dropping the earliest requests
Breadth-first searchExplore everything one step away before going two steps
Producer/consumer pipelinesOne side adds, the other takes, in order

Worked example: a simple job queue

public record PrintJob(string Document, int Pages);

public class PrintSpooler
{
    private readonly Queue<PrintJob> _queue = new();

    public void Submit(PrintJob job)
    {
        _queue.Enqueue(job);
        Console.WriteLine($"Queued '{job.Document}' ({_queue.Count} waiting)");
    }

    public void RunAll()
    {
        while (_queue.Count > 0)
        {
            PrintJob job = _queue.Dequeue();
            Console.WriteLine($"Printing '{job.Document}' - {job.Pages} pages");
        }
        Console.WriteLine("Spooler idle.");
    }
}

var spooler = new PrintSpooler();
spooler.Submit(new PrintJob("Invoice.pdf", 2));
spooler.Submit(new PrintJob("Report.docx", 40));
spooler.Submit(new PrintJob("Memo.txt", 1));
spooler.RunAll();
// Printing 'Invoice.pdf' - 2 pages     <- submitted first, printed first
// Printing 'Report.docx' - 40 pages
// Printing 'Memo.txt' - 1 pages

PriorityQueue - the urgent one first

Sometimes order of arrival is not what matters. PriorityQueue (.NET 6+) always hands back the item with the lowest priority value, which makes it the right tool for schedulers, triage, and Dijkstra's shortest-path algorithm. Internally it is a heap.

// PriorityQueue<TElement, TPriority> - lowest priority number comes out first
var triage = new PriorityQueue<string, int>();

triage.Enqueue("Sprained ankle", 3);
triage.Enqueue("Chest pain", 1);          // most urgent
triage.Enqueue("Broken arm", 2);

while (triage.Count > 0)
    Console.WriteLine(triage.Dequeue());

// Chest pain
// Broken arm
// Sprained ankle
A priority queue is not stable

Two items with the same priority can come out in any order. If ties must be broken by arrival time, make the priority a tuple: Enqueue(item, (priority, sequenceNumber)) with a PriorityQueue<string, (int, long)>.
