Arrays & Lists

The simplest and most-used data structure: a numbered row of slots, side by side in memory.

Arrays in one sentence

An array is a row of equal-sized boxes, side by side in memory, numbered from 0. Because the boxes are the same size and next to each other, the computer can jump to box number 4,000 by arithmetic alone - instantly, without touching boxes 0 to 3,999.

Why index access is instant

If the array starts at memory address 1000 and each int takes 4 bytes, then item i lives at 1000 + (i * 4). One multiply, one add, done - the same amount of work whether the array holds 10 items or 10 million. That is what O(1) means.

int[] numbers = { 10, 20, 30, 40, 50 };
10
index 0 - addr 1000
20
index 1 - addr 1004
30
index 2 - addr 1008
40
index 3 - addr 1012
50
index 4 - addr 1016

The same layout is also why arrays are fast to loop over: the CPU pulls neighbouring memory into its cache, so the next item is usually already there.

Arrays in C#

// Declare with a fixed size - every slot starts at the type's default (0 for int)
int[] scores = new int[5];
scores[0] = 90;
scores[4] = 75;

// Or declare and fill in one go
int[] numbers = { 10, 20, 30, 40, 50 };
string[] names = new string[] { "Ada", "Alan", "Grace" };

Console.WriteLine(numbers[2]);          // 30      - O(1)
Console.WriteLine(numbers.Length);      // 5
Console.WriteLine(numbers[^1]);         // 50      - ^1 means "last"

// numbers[10] = 1;                     // IndexOutOfRangeException at run time

foreach (int n in numbers)
    Console.Write(n + " ");             // 10 20 30 40 50

Useful array operations

int[] data = { 5, 3, 8, 1, 9 };

Array.Sort(data);                              // 1 3 5 8 9        O(n log n)
Array.Reverse(data);                           // 9 8 5 3 1        O(n)
int idx = Array.IndexOf(data, 5);              // 2                O(n)
Array.Clear(data, 0, data.Length);             // all back to 0

int[] copy = new int[5];
Array.Copy(data, copy, 5);                     // O(n)

int[] slice = data[1..4];                      // items 1, 2, 3 (C# 8 ranges)
int[] joined = data.Concat(copy).ToArray();    // LINQ, allocates a new array

Two-dimensional arrays

// Rectangular: one block of memory, every row the same length
int[,] grid = new int[3, 4];        // 3 rows, 4 columns
grid[1, 2] = 7;
Console.WriteLine(grid.GetLength(0));   // 3 rows
Console.WriteLine(grid.GetLength(1));   // 4 columns

int[,] board =
{
    { 1, 2, 3 },
    { 4, 5, 6 }
};

for (int row = 0; row < board.GetLength(0); row++)
{
    for (int col = 0; col < board.GetLength(1); col++)
        Console.Write(board[row, col] + " ");
    Console.WriteLine();
}

// Jagged: an array of arrays - rows can have different lengths
int[][] jagged = new int[3][];
jagged[0] = new int[] { 1, 2 };
jagged[1] = new int[] { 3, 4, 5, 6 };
jagged[2] = new int[] { 7 };
Console.WriteLine(jagged[1][3]);        // 6
The limitation: arrays cannot grow

new int[5] is five slots forever. Adding a sixth item means allocating a bigger array and copying everything across. Doing that by hand on every insert is tedious and slow - which is exactly the problem List solves.

List<T> - the resizable array

List<T> is an array that manages its own growth. Internally it holds a normal array plus a count; when the array fills up, it allocates a bigger one (doubling the capacity) and copies everything over.

var names = new List<string>();

names.Add("Ada");                     // O(1) amortised
names.Add("Alan");
names.Add("Grace");

names.Insert(1, "Barbara");           // O(n) - everything after shifts right
names.Remove("Alan");                 // O(n) - find, then shift left
names.RemoveAt(0);                    // O(n)

Console.WriteLine(names[0]);          // Barbara            O(1)
Console.WriteLine(names.Count);       // 2
Console.WriteLine(names.Contains("Grace"));   // True       O(n)
Console.WriteLine(names.IndexOf("Grace"));    // 1          O(n)

names.Sort();                         // O(n log n)
names.Clear();

Capacity vs Count

var list = new List<int>();
Console.WriteLine($"{list.Count} items, capacity {list.Capacity}");   // 0 items, capacity 0

for (int i = 0; i < 9; i++)
{
    list.Add(i);
    Console.WriteLine($"{list.Count} items, capacity {list.Capacity}");
}
// 1/4, 2/4, 3/4, 4/4, 5/8, 6/8, 7/8, 8/8, 9/16  <- capacity doubles when full

// If you know the size up front, say so - it avoids every intermediate copy
var preSized = new List<int>(capacity: 10_000);
Why doubling matters

Growing by one each time would make n adds cost O(n²). Doubling means the copies get rarer as the list grows, so the average cost of Add stays O(1) - the "amortised" guarantee from the Big-O page.

Building a dynamic array yourself

Fifty lines that show exactly what List<T> does behind the scenes:

public class MyList<T>
{
    private T[] _items = new T[4];       // the backing array
    private int _count;                  // how many slots are actually in use

    public int Count => _count;
    public int Capacity => _items.Length;

    public T this[int index]             // indexer: enables myList[0]
    {
        get
        {
            if (index < 0 || index >= _count) throw new IndexOutOfRangeException();
            return _items[index];
        }
        set
        {
            if (index < 0 || index >= _count) throw new IndexOutOfRangeException();
            _items[index] = value;
        }
    }

    public void Add(T item)
    {
        if (_count == _items.Length) Grow();   // full? get a bigger array first
        _items[_count] = item;
        _count++;
    }

    public void Insert(int index, T item)
    {
        if (index < 0 || index > _count) throw new ArgumentOutOfRangeException(nameof(index));
        if (_count == _items.Length) Grow();

        // Shift everything from index onwards one slot right - this is the O(n) part
        for (int i = _count; i > index; i--)
            _items[i] = _items[i - 1];

        _items[index] = item;
        _count++;
    }

    public void RemoveAt(int index)
    {
        if (index < 0 || index >= _count) throw new ArgumentOutOfRangeException(nameof(index));

        // Shift everything after index one slot left
        for (int i = index; i < _count - 1; i++)
            _items[i] = _items[i + 1];

        _count--;
        _items[_count] = default!;       // release the reference so the GC can collect
    }

    public int IndexOf(T item)
    {
        for (int i = 0; i < _count; i++)
            if (EqualityComparer<T>.Default.Equals(_items[i], item)) return i;
        return -1;
    }

    private void Grow()
    {
        var bigger = new T[_items.Length * 2];
        Array.Copy(_items, bigger, _count);   // the expensive step, done rarely
        _items = bigger;
    }
}
var list = new MyList<string>();
list.Add("a");
list.Add("b");
list.Add("c");
list.Insert(1, "x");
list.RemoveAt(0);

for (int i = 0; i < list.Count; i++)
    Console.Write(list[i] + " ");        // x b c

Console.WriteLine($"\nCount {list.Count}, capacity {list.Capacity}");  // Count 3, capacity 4

Choosing between them

Use an array whenUse List<T> when
The size is known and fixedThe size changes as you go
You need the last drop of performance in a hot loopYou want convenience methods - Add, Remove, Sort, LINQ
An API you are calling demands oneWhich is nearly always, in application code
Working with a fixed grid or matrixBuilding up a collection of unknown length
Practical defaults

Use List<T> unless you have a reason not to. Pre-size it when you know roughly how many items are coming. Expose it as IReadOnlyList<T> or IEnumerable<T> from public members so callers cannot modify your internals - see Encapsulation.

Common mistakes

// MISTAKE 1: modifying a collection while iterating it
foreach (var item in list)
    if (item.IsExpired) list.Remove(item);      // throws InvalidOperationException

// FIX A: iterate backwards by index
for (int i = list.Count - 1; i >= 0; i--)
    if (list[i].IsExpired) list.RemoveAt(i);

// FIX B: one call, and clearer
list.RemoveAll(x => x.IsExpired);
// MISTAKE 2: Insert(0, ...) in a loop is O(n²)
for (int i = 0; i < 100_000; i++)
    list.Insert(0, i);                          // every insert shifts everything

// FIX: add at the end, then reverse once
for (int i = 0; i < 100_000; i++) list.Add(i);
list.Reverse();
// MISTAKE 3: assuming a copied list is a deep copy
var original = new List<Customer> { customer };
var copied = new List<Customer>(original);      // a NEW list...
copied[0].Name = "Changed";                     // ...pointing at the SAME objects
Console.WriteLine(original[0].Name);            // Changed
