Data Structures & Algorithms

A data structure decides how your data is stored. An algorithm decides what you do with it. Pick the right pair and slow code becomes fast code.

Two words, defined

A data structure is a way of organising data in memory - a shelf, a queue, a filing cabinet, a family tree. An algorithm is a step-by-step procedure for getting something done - find this, sort that, walk everything. Choosing the right pair is most of what "writing efficient code" means.

Why it matters, with numbers

Suppose you have 100,000 customer records and you need to look one up by ID, 1,000 times. Same task, two data structures:

var list = new List<Customer>(customers);                       // 100,000 items
var byId = customers.ToDictionary(c => c.Id);                   // same data, hashed

// Option A: scan the list every time - up to 100,000 comparisons per lookup
Customer? a = list.FirstOrDefault(c => c.Id == 98_765);

// Option B: hash the key and jump straight to it - roughly 1 comparison
byId.TryGetValue(98_765, out Customer? b);
ApproachComparisons for 1,000 lookupsTypical time
List scan~50,000,000Seconds
Dictionary lookup~1,000Under a millisecond

No cleverness, no micro-optimisation, no extra hardware. One line changed, and a report that took ten seconds now takes ten milliseconds. That is why this topic is worth a week of your time.

How to choose a data structure

Ask what you will do with the data most often, then pick the structure that makes that operation cheap:

What you do mostUseWhy
Access by position, iterate in orderList / arrayContiguous memory, index arithmetic is instant
Look up by a keyDictionaryHashing jumps straight to the bucket
Ask "have I seen this before?"HashSetMembership test independent of size
Process newest first (undo, backtracking)StackLast in, first out
Process oldest first (work queue)QueueFirst in, first out
Always take the most urgent itemPriorityQueueA heap keeps the smallest at the top
Keep items sorted as you insertSortedDictionary / SortedSetBalanced tree, ordered traversal
Insert and remove constantly at both endsLinkedListNo shifting of elements
Model connections between thingsGraph (adjacency list)Directly represents relationships

The 90% answer

In everyday C#, List and Dictionary cover the large majority of cases. Learn where those two stop being the right answer and you have learned the practical half of this subject.

The algorithms worth knowing

AlgorithmWhat it doesCost

Measure before you optimise

Knowing Big-O tells you which solution scales. It does not tell you which one is faster on your data at your size - a linear scan of 20 items beats a dictionary. Use BenchmarkDotNet or a profiler before rewriting working code.
