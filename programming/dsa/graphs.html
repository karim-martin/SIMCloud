Graphs

Things and the connections between them - the structure behind maps, networks, and dependencies.

Graph in one sentence

A graph is a set of things (vertices, or nodes) and the connections between them (edges). A road map, a social network, a set of microservices calling each other, and a build dependency chart are all graphs.

Vocabulary

TermMeaningExample
Vertex (node)One thing in the graphA city, a person, a service
EdgeA connection between two verticesA road, a friendship, an API call
UndirectedEdges work both waysFacebook friendship
Directed (digraph)Edges have a directionTwitter follows, task dependencies
WeightedEach edge carries a costDistance, latency, price
PathA sequence of edges from one vertex to anotherA -> B -> D
CycleA path that returns to where it startedA circular dependency
DAGDirected acyclic graph - directed, no cyclesBuild pipelines, git history
ConnectedEvery vertex is reachable from every otherA network with no isolated islands

A tree is just a special graph: connected, directed downwards, and with no cycles. Everything on this page also works on trees.

Two ways to store a graph

Adjacency listAdjacency matrix
ShapeEach vertex holds a list of its neighboursA V×V grid of true/false or weights
MemoryO(V + E)O(V²)
"Is there an edge A-B?"O(degree of A)O(1)
"List A's neighbours"O(degree of A)O(V)
Best forSparse graphs - most real onesDense graphs, or lots of edge lookups

Adjacency lists are the default in application code. A social network with a million users and fifty friends each needs 50 million list entries - but a matrix would need a trillion cells.

Building a graph in C#

public class Graph<T> where T : notnull
{
    // Vertex -> its neighbours. This IS the adjacency list.
    private readonly Dictionary<T, List<T>> _adjacency = new();
    private readonly bool _directed;

    public Graph(bool directed = false) => _directed = directed;

    public IEnumerable<T> Vertices => _adjacency.Keys;

    public void AddVertex(T vertex)
    {
        if (!_adjacency.ContainsKey(vertex))
            _adjacency[vertex] = new List<T>();
    }

    public void AddEdge(T from, T to)
    {
        AddVertex(from);
        AddVertex(to);

        _adjacency[from].Add(to);
        if (!_directed) _adjacency[to].Add(from);   // undirected: both directions
    }

    public IReadOnlyList<T> NeighboursOf(T vertex) =>
        _adjacency.TryGetValue(vertex, out List<T>? list) ? list : Array.Empty<T>();

    public bool HasEdge(T from, T to) => NeighboursOf(from).Contains(to);
}
var cities = new Graph<string>(directed: false);
cities.AddEdge("London", "Oxford");
cities.AddEdge("London", "Cambridge");
cities.AddEdge("Oxford", "Bristol");
cities.AddEdge("Cambridge", "Norwich");
cities.AddEdge("Bristol", "Cardiff");

Console.WriteLine(string.Join(", ", cities.NeighboursOf("London")));  // Oxford, Cambridge
Console.WriteLine(cities.HasEdge("Oxford", "London"));                // True - undirected

Breadth-first search (BFS)

Explore everything one step away, then everything two steps away, and so on. Uses a queue. Because it expands in rings, the first time BFS reaches a vertex it has found the fewest-edges path to it.

public static List<T> BreadthFirst<T>(Graph<T> graph, T start) where T : notnull
{
    var visited = new HashSet<T> { start };      // stops us revisiting - and looping forever
    var queue = new Queue<T>();
    var order = new List<T>();

    queue.Enqueue(start);

    while (queue.Count > 0)
    {
        T current = queue.Dequeue();
        order.Add(current);

        foreach (T neighbour in graph.NeighboursOf(current))
        {
            if (visited.Add(neighbour))          // Add returns false if already seen
                queue.Enqueue(neighbour);
        }
    }

    return order;
}

Console.WriteLine(string.Join(" -> ", BreadthFirst(cities, "London")));
// London -> Oxford -> Cambridge -> Bristol -> Norwich -> Cardiff

BFS for the shortest path

Record which vertex you came from, then walk the trail backwards at the end:

public static List<T>? ShortestPath<T>(Graph<T> graph, T start, T goal) where T : notnull
{
    if (EqualityComparer<T>.Default.Equals(start, goal)) return new List<T> { start };

    var cameFrom = new Dictionary<T, T>();       // child -> parent
    var visited = new HashSet<T> { start };
    var queue = new Queue<T>();
    queue.Enqueue(start);

    while (queue.Count > 0)
    {
        T current = queue.Dequeue();

        foreach (T neighbour in graph.NeighboursOf(current))
        {
            if (!visited.Add(neighbour)) continue;

            cameFrom[neighbour] = current;

            if (EqualityComparer<T>.Default.Equals(neighbour, goal))
                return Rebuild(cameFrom, start, goal);

            queue.Enqueue(neighbour);
        }
    }

    return null;                                  // no route exists
}

private static List<T> Rebuild<T>(Dictionary<T, T> cameFrom, T start, T goal) where T : notnull
{
    var path = new List<T> { goal };
    T current = goal;

    while (!EqualityComparer<T>.Default.Equals(current, start))
    {
        current = cameFrom[current];
        path.Add(current);
    }

    path.Reverse();                               // we built it backwards
    return path;
}

List<string>? route = ShortestPath(cities, "London", "Cardiff");
Console.WriteLine(route is null ? "No route" : string.Join(" -> ", route));
// London -> Oxford -> Bristol -> Cardiff

Depth-first search (DFS)

Follow one path as far as it goes, then back up and try the next. Uses a stack - either an explicit one, or the call stack via recursion.

// Recursive - the call stack does the remembering
public static void DepthFirst<T>(Graph<T> graph, T current, HashSet<T> visited, List<T> order)
    where T : notnull
{
    if (!visited.Add(current)) return;            // already been here
    order.Add(current);

    foreach (T neighbour in graph.NeighboursOf(current))
        DepthFirst(graph, neighbour, visited, order);
}

// Iterative - an explicit stack, and no risk of a stack overflow on deep graphs
public static List<T> DepthFirstIterative<T>(Graph<T> graph, T start) where T : notnull
{
    var visited = new HashSet<T>();
    var stack = new Stack<T>();
    var order = new List<T>();

    stack.Push(start);

    while (stack.Count > 0)
    {
        T current = stack.Pop();
        if (!visited.Add(current)) continue;
        order.Add(current);

        foreach (T neighbour in graph.NeighboursOf(current))
            if (!visited.Contains(neighbour))
                stack.Push(neighbour);
    }

    return order;
}

var order = new List<string>();
DepthFirst(cities, "London", new HashSet<string>(), order);
Console.WriteLine(string.Join(" -> ", order));
// London -> Oxford -> Bristol -> Cardiff -> Cambridge -> Norwich
BFS or DFS?

Same cost - O(V + E) - and the only structural difference is queue versus stack. Use BFS when you want the shortest hop count or the nearest match. Use DFS when you need to explore whole branches: cycle detection, topological sorting, connected components, maze solving.

Detecting a cycle

A circular dependency is a cycle in a directed graph. Detect it with DFS by tracking the vertices on the current path, not just the ones already visited:

public static bool HasCycle<T>(Graph<T> graph) where T : notnull
{
    var visited = new HashSet<T>();
    var onCurrentPath = new HashSet<T>();

    foreach (T vertex in graph.Vertices)
        if (Visit(vertex))
            return true;

    return false;

    bool Visit(T vertex)
    {
        if (onCurrentPath.Contains(vertex)) return true;    // looped back: cycle
        if (!visited.Add(vertex)) return false;             // fully explored already

        onCurrentPath.Add(vertex);

        foreach (T neighbour in graph.NeighboursOf(vertex))
            if (Visit(neighbour)) return true;

        onCurrentPath.Remove(vertex);                       // done with this branch
        return false;
    }
}

var deps = new Graph<string>(directed: true);
deps.AddEdge("api", "database");
deps.AddEdge("web", "api");
Console.WriteLine(HasCycle(deps));      // False

deps.AddEdge("database", "web");        // now it loops
Console.WriteLine(HasCycle(deps));      // True

Topological sort

Given a DAG of dependencies, produce an order in which every item comes after everything it depends on. This is how build systems, package managers, and task schedulers decide what to run first.

// Kahn's algorithm: repeatedly take a vertex with no remaining dependencies
public static List<T>? TopologicalSort<T>(Graph<T> graph) where T : notnull
{
    var inDegree = graph.Vertices.ToDictionary(v => v, _ => 0);

    foreach (T vertex in graph.Vertices)
        foreach (T neighbour in graph.NeighboursOf(vertex))
            inDegree[neighbour]++;

    // Start with everything that depends on nothing
    var ready = new Queue<T>(inDegree.Where(p => p.Value == 0).Select(p => p.Key));
    var result = new List<T>();

    while (ready.Count > 0)
    {
        T current = ready.Dequeue();
        result.Add(current);

        foreach (T neighbour in graph.NeighboursOf(current))
            if (--inDegree[neighbour] == 0)
                ready.Enqueue(neighbour);
    }

    // Anything left has an unsatisfiable dependency - the graph has a cycle
    return result.Count == inDegree.Count ? result : null;
}

var build = new Graph<string>(directed: true);
build.AddEdge("compile", "test");        // compile must happen before test
build.AddEdge("test", "package");
build.AddEdge("package", "deploy");
build.AddEdge("lint", "package");

Console.WriteLine(string.Join(" -> ", TopologicalSort(build)!));
// compile -> lint -> test -> package -> deploy   (one valid order)

Weighted graphs and Dijkstra's algorithm

BFS finds the fewest hops. When edges have different costs - distance, latency, price - you need Dijkstra's algorithm, which is BFS with a priority queue instead of a plain queue.

public class WeightedGraph
{
    private readonly Dictionary<string, List<(string To, int Cost)>> _edges = new();

    public void AddEdge(string from, string to, int cost)
    {
        if (!_edges.ContainsKey(from)) _edges[from] = new();
        if (!_edges.ContainsKey(to))   _edges[to]   = new();

        _edges[from].Add((to, cost));
        _edges[to].Add((from, cost));          // undirected
    }

    public (int Cost, List<string> Path)? Shortest(string start, string goal)
    {
        var best = new Dictionary<string, int> { [start] = 0 };   // cheapest known cost
        var cameFrom = new Dictionary<string, string>();
        var queue = new PriorityQueue<string, int>();
        var settled = new HashSet<string>();

        queue.Enqueue(start, 0);

        while (queue.TryDequeue(out string? current, out int costSoFar))
        {
            if (!settled.Add(current)) continue;          // already finalised
            if (current == goal) break;

            foreach ((string next, int edgeCost) in _edges[current])
            {
                int newCost = costSoFar + edgeCost;

                // Only keep it if it beats the best route found so far
                if (best.TryGetValue(next, out int known) && known <= newCost) continue;

                best[next] = newCost;
                cameFrom[next] = current;
                queue.Enqueue(next, newCost);
            }
        }

        if (!best.ContainsKey(goal)) return null;

        var path = new List<string> { goal };
        for (string at = goal; at != start; at = cameFrom[at])
            path.Add(cameFrom[at]);
        path.Reverse();

        return (best[goal], path);
    }
}
var roads = new WeightedGraph();
roads.AddEdge("London", "Oxford", 60);
roads.AddEdge("Oxford", "Bristol", 75);
roads.AddEdge("London", "Bristol", 120);      // direct - cheaper than 60 + 75 via Oxford
roads.AddEdge("Bristol", "Cardiff", 45);

var result = roads.Shortest("London", "Cardiff");
Console.WriteLine($"{result!.Value.Cost} miles: {string.Join(" -> ", result.Value.Path)}");
// 165 miles: London -> Bristol -> Cardiff
Dijkstra needs non-negative weights

The algorithm assumes that extending a path never makes it cheaper. With negative edge costs it can settle on a wrong answer - use Bellman-Ford there instead.

Cost summary

V = number of vertices, E = number of edges.

AlgorithmTimeSpaceFinds
BFSO(V + E)O(V)Fewest-hops path, level order
DFSO(V + E)O(V)Reachability, cycles, components
Topological sortO(V + E)O(V)A valid dependency order
Dijkstra (with a heap)O((V + E) log V)O(V)Cheapest weighted path
Always keep a visited set

Forgetting it is the classic graph bug: the traversal follows an edge back to where it came from and loops forever. Trees are safe without one only because they have no cycles.
