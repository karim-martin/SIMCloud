Pillar 4: Polymorphism

One interface, many implementations. Write the calling code once and let each object supply its own behaviour.

Polymorphism in one sentence

"Poly" = many, "morph" = form. You write one line - shape.Draw() - and the object decides what actually happens. A circle draws a circle, a square draws a square, and your calling code never asks which is which.

Compile-time: method overloading

Several methods share a name; the compiler picks one based on the number and types of the arguments. The methods must differ in their parameter list - the return type alone is not enough.

public class Calculator
{
    public int Add(int a, int b) => a + b;

    public double Add(double a, double b) => a + b;

    public int Add(int a, int b, int c) => a + b + c;

    public string Add(string a, string b) => a + b;

    // Variable number of arguments
    public int Add(params int[] numbers)
    {
        int total = 0;
        foreach (int n in numbers) total += n;
        return total;
    }

    // NOT allowed - differs only by return type
    // public double Add(int a, int b) => a + b;   // compile error
}
var calc = new Calculator();
Console.WriteLine(calc.Add(2, 3));            // 5      -> Add(int, int)
Console.WriteLine(calc.Add(2.5, 3.1));        // 5.6    -> Add(double, double)
Console.WriteLine(calc.Add(1, 2, 3));         // 6      -> Add(int, int, int)
Console.WriteLine(calc.Add("Hello, ", "Ada"));// Hello, Ada
Console.WriteLine(calc.Add(1, 2, 3, 4, 5));   // 15     -> Add(params int[])

Constructors overload the same way, which is how a class can offer several ways to be created.

Runtime: method overriding

This is the important one. A base class declares a virtual or abstract method; each derived class overrides it; and the runtime picks the implementation based on what the object really is - not what the variable is declared as.

public abstract class Shape
{
    public string Name { get; }
    protected Shape(string name) => Name = name;

    // Every shape has an area, but there is no sensible generic formula
    public abstract double Area();

    // Shared behaviour that uses the subclass's Area()
    public void Describe() =>
        Console.WriteLine($"{Name} has an area of {Area():F2}");
}

public class Circle : Shape
{
    private readonly double _radius;
    public Circle(double radius) : base("Circle") => _radius = radius;

    public override double Area() => Math.PI * _radius * _radius;
}

public class Rectangle : Shape
{
    private readonly double _width, _height;
    public Rectangle(double width, double height) : base("Rectangle")
    {
        _width = width;
        _height = height;
    }

    public override double Area() => _width * _height;
}

public class Triangle : Shape
{
    private readonly double _baseLength, _height;
    public Triangle(double baseLength, double height) : base("Triangle")
    {
        _baseLength = baseLength;
        _height = height;
    }

    public override double Area() => 0.5 * _baseLength * _height;
}

Now the payoff. One loop, one variable type, three different behaviours:

// A list of the BASE type, holding objects of three DIFFERENT types
List<Shape> shapes = new()
{
    new Circle(3),
    new Rectangle(4, 5),
    new Triangle(6, 2)
};

double total = 0;
foreach (Shape shape in shapes)
{
    shape.Describe();      // each object runs its OWN Area()
    total += shape.Area();
}

Console.WriteLine($"Total area: {total:F2}");
Circle has an area of 28.27
Rectangle has an area of 20.00
Triangle has an area of 6.00
Total area: 54.27
Why this matters more than it looks

Add a Hexagon class tomorrow and that loop still works, unchanged and untested. Without polymorphism you would be maintaining a growing if (shape is Circle) ... else if (shape is Rectangle) ... chain in every place that touches a shape. Polymorphism replaces that chain with one method call.

Polymorphism through interfaces

You do not need a shared base class. Unrelated types that implement the same interface are just as interchangeable - and this is the form you will use most in real .NET code.

public interface IDiscountRule
{
    string Description { get; }
    decimal Apply(decimal price);
}

public class PercentageDiscount : IDiscountRule
{
    private readonly decimal _percent;
    public PercentageDiscount(decimal percent) => _percent = percent;

    public string Description => $"{_percent}% off";
    public decimal Apply(decimal price) => price * (1 - _percent / 100m);
}

public class FixedAmountDiscount : IDiscountRule
{
    private readonly decimal _amount;
    public FixedAmountDiscount(decimal amount) => _amount = amount;

    public string Description => $"{_amount:C} off";
    public decimal Apply(decimal price) => Math.Max(0m, price - _amount);
}

public class NoDiscount : IDiscountRule
{
    public string Description => "No discount";
    public decimal Apply(decimal price) => price;      // the "null object" pattern
}
decimal price = 100m;

IDiscountRule[] rules =
{
    new PercentageDiscount(10m),
    new FixedAmountDiscount(15m),
    new NoDiscount()
};

foreach (IDiscountRule rule in rules)
    Console.WriteLine($"{rule.Description,-15} -> {rule.Apply(price):C}");
10% off         -> £90.00
£15.00 off      -> £85.00
No discount     -> £100.00

Checking the real type when you must

Good polymorphic design usually removes the need to ask "what type is this?". When you genuinely need to - deserialising, integrating with a library, handling a closed set of cases - C# pattern matching is the modern way.

Shape shape = new Circle(3);

// "is" with a pattern: test and cast in one step
if (shape is Circle circle)
    Console.WriteLine($"A circle, area {circle.Area():F2}");

// "as" returns null instead of throwing when the cast fails
Rectangle? rect = shape as Rectangle;
Console.WriteLine(rect is null);          // True

// switch expression over types
string label = shape switch
{
    Circle c when c.Area() > 100 => "Big circle",
    Circle                       => "Circle",
    Rectangle r                  => $"Rectangle of area {r.Area()}",
    null                         => "Nothing",
    _                            => "Some other shape"
};
Console.WriteLine(label);                 // Circle
A type check is often a missed override

If you find yourself writing if (x is Circle) ... else if (x is Square) ..., ask whether that behaviour belongs on the shape itself as a virtual method. Every new subclass would otherwise force you to find and update every one of those chains.

Operator overloading

C# also lets you give operators new meaning for your own types. Use it sparingly, and only where the meaning is obvious.

public readonly struct Money
{
    public decimal Amount { get; }
    public string Currency { get; }

    public Money(decimal amount, string currency)
    {
        Amount = amount;
        Currency = currency;
    }

    public static Money operator +(Money a, Money b)
    {
        if (a.Currency != b.Currency)
            throw new InvalidOperationException("Cannot add different currencies.");
        return new Money(a.Amount + b.Amount, a.Currency);
    }

    public static Money operator *(Money m, int quantity) =>
        new Money(m.Amount * quantity, m.Currency);

    public override string ToString() => $"{Amount:0.00} {Currency}";
}

var subtotal = new Money(19.99m, "GBP") + new Money(5.00m, "GBP");
Console.WriteLine(subtotal);                        // 24.99 GBP
Console.WriteLine(new Money(2.50m, "GBP") * 4);     // 10.00 GBP

A worked example: one report, many formats

Polymorphism at its most useful - the caller does not know or care which format it is producing.

public interface IExporter
{
    string Format { get; }
    string Export(IReadOnlyList<(string Name, decimal Total)> rows);
}

public class CsvExporter : IExporter
{
    public string Format => "CSV";
    public string Export(IReadOnlyList<(string Name, decimal Total)> rows) =>
        "name,total\n" + string.Join("\n", rows.Select(r => $"{r.Name},{r.Total}"));
}

public class JsonExporter : IExporter
{
    public string Format => "JSON";
    public string Export(IReadOnlyList<(string Name, decimal Total)> rows) =>
        "[" + string.Join(",", rows.Select(r => $"{{\"name\":\"{r.Name}\",\"total\":{r.Total}}}")) + "]";
}

public class MarkdownExporter : IExporter
{
    public string Format => "Markdown";
    public string Export(IReadOnlyList<(string Name, decimal Total)> rows) =>
        "| Name | Total |\n|---|---|\n" +
        string.Join("\n", rows.Select(r => $"| {r.Name} | {r.Total} |"));
}

// The caller: written once, works with every current and future exporter
public class ReportService
{
    public void Save(IExporter exporter, IReadOnlyList<(string, decimal)> rows)
    {
        Console.WriteLine($"--- {exporter.Format} ---");
        Console.WriteLine(exporter.Export(rows));
    }
}
var rows = new List<(string, decimal)> { ("North", 1200m), ("South", 980m) };
var service = new ReportService();

foreach (IExporter exporter in new IExporter[]
         { new CsvExporter(), new JsonExporter(), new MarkdownExporter() })
{
    service.Save(exporter, rows);
}
