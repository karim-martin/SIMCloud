Building Blocks

Six pieces make up every object-oriented program. Learn these and the four pillars become easy.

The cookie-cutter analogy

A class is the cookie cutter. An object is a cookie. One cutter, many cookies - each with its own icing. The cutter defines the shape; each cookie carries its own state.

1. Class - the blueprint

A class defines what every object of that type will know (data) and what it will be able to do (behaviour). Writing a class creates no data by itself - it is a description, like a house plan.

public class Car
{
    // What every Car knows
    public string Make { get; set; }
    public string Model { get; set; }
    public int Year { get; set; }

    // What every Car can do
    public void Start()
    {
        Console.WriteLine($"{Make} {Model} is starting.");
    }
}
PartMeaning
publicAccessibility - any code can use this class. See Encapsulation for the full list.
classThe keyword that declares a reference type.
CarThe class name. C# convention is PascalCase, and a noun.
{ ... }The class body - its members (fields, properties, methods, constructors).

2. Object - an instance of a class

An object is created with new. Each object gets its own copy of the data, so changing one never affects another.

Car car1 = new Car { Make = "Toyota", Model = "Corolla", Year = 2020 };
Car car2 = new Car { Make = "Honda",  Model = "Civic",   Year = 2023 };

car1.Start();                    // Toyota Corolla is starting.
car2.Start();                    // Honda Civic is starting.

car1.Year = 2021;                // only car1 changes
Console.WriteLine(car2.Year);    // 2023
Reference types: the variable is not the object

A class is a reference type. The variable holds the address of the object, not the object itself. So two variables can point at the same object:

Car a = new Car { Make = "Ford" };
Car b = a;                       // b points at the SAME object as a
b.Make = "Mazda";
Console.WriteLine(a.Make);       // Mazda  - there is only one object

Car c = new Car { Make = "Ford" };
Console.WriteLine(ReferenceEquals(a, c));  // False - different objects

If you want a value type - copied on assignment - use a struct. For everyday application code, classes are the default choice.

3. Attributes - fields and properties

"Attribute" is the general OOP word for the data an object holds. C# gives you two forms of it.

Fields

A field is a raw variable inside the class. Convention: keep fields private, name them _camelCase.

public class Thermostat
{
    private double _currentTemp;        // private field: internal state
    private readonly string _serial;    // readonly: set once, in the constructor

    public Thermostat(string serial)
    {
        _serial = serial;
    }
}

Properties

A property looks like a field from the outside but is really a pair of methods (a get and a set). That is what lets you add validation later without breaking any calling code.

public class Product
{
    // 1. Auto-property - the compiler creates the hidden backing field
    public string Name { get; set; }

    // 2. Read-only from outside, settable inside the class
    public DateTime CreatedUtc { get; private set; } = DateTime.UtcNow;

    // 3. Init-only - can be set when the object is created, never after
    public string Sku { get; init; }

    // 4. Full property with a backing field and validation
    private decimal _price;
    public decimal Price
    {
        get => _price;
        set
        {
            if (value < 0)
                throw new ArgumentOutOfRangeException(nameof(value), "Price cannot be negative.");
            _price = value;
        }
    }

    // 5. Computed property - no stored data, calculated on each read
    public decimal PriceWithVat => _price * 1.20m;
}
var p = new Product { Name = "Keyboard", Sku = "KB-01", Price = 50m };
Console.WriteLine(p.PriceWithVat);   // 60.0
// p.Sku = "KB-02";                  // compile error: init-only
// p.Price = -5m;                    // throws ArgumentOutOfRangeException
FieldProperty
A variable that stores dataA method pair that looks like a variable
No place to add validationValidation, logging, or lazy loading can be added in the setter
Keep them privateThis is what you expose publicly

4. Methods - the operations

A method is a named block of code that acts on the object's data. Signature: accessibility, return type, name, parameters.

public class ShoppingCart
{
    private readonly List<decimal> _lineTotals = new();

    // void: does something, returns nothing
    public void AddLine(decimal amount)
    {
        _lineTotals.Add(amount);
    }

    // Returns a value
    public decimal Total()
    {
        decimal sum = 0m;
        foreach (decimal line in _lineTotals)
            sum += line;
        return sum;
    }

    // Expression-bodied: shorthand for a single-expression method
    public int LineCount() => _lineTotals.Count;

    // Optional parameter with a default value
    public decimal TotalWithShipping(decimal shipping = 4.99m) => Total() + shipping;

    // Static: belongs to the class, not to any object
    public static ShoppingCart Empty() => new ShoppingCart();
}
var cart = ShoppingCart.Empty();   // static: called on the CLASS
cart.AddLine(19.99m);              // instance: called on an OBJECT
cart.AddLine(5.00m);
Console.WriteLine(cart.Total());               // 24.99
Console.WriteLine(cart.TotalWithShipping());   // 29.98
Instance vs static

An instance method needs an object (cart.Total()) because it reads that object's data. A static method belongs to the class itself (Math.Max(1, 2)) and cannot see instance data.

Method overloading

Several methods can share a name as long as their parameters differ. The compiler picks the right one. This is one half of polymorphism.

public class Printer
{
    public void Print(string text)   => Console.WriteLine(text);
    public void Print(int number)    => Console.WriteLine($"Number: {number}");
    public void Print(string text, int times)
    {
        for (int i = 0; i < times; i++)
            Console.WriteLine(text);
    }
}

var printer = new Printer();
printer.Print("Hello");        // picks Print(string)
printer.Print(42);             // picks Print(int)
printer.Print("Hi", 3);        // picks Print(string, int)

5. Message passing - objects calling each other

Objects rarely work alone. "Message passing" is the OOP term for one object invoking a method on another: receiver.Method(arguments). The caller says what it wants; the receiver decides how.

public class EmailService
{
    public void Send(string to, string subject)
    {
        Console.WriteLine($"Email to {to}: {subject}");
    }
}

public class InventoryService
{
    private int _stock = 10;

    public bool TryReserve(int quantity)
    {
        if (quantity > _stock) return false;
        _stock -= quantity;
        return true;
    }
}

public class OrderProcessor
{
    private readonly EmailService _email;
    private readonly InventoryService _inventory;

    // The collaborators are handed in - this is dependency injection
    public OrderProcessor(EmailService email, InventoryService inventory)
    {
        _email = email;
        _inventory = inventory;
    }

    public void Place(string customerEmail, int quantity)
    {
        // Message 1: ask inventory to reserve stock
        if (!_inventory.TryReserve(quantity))
        {
            _email.Send(customerEmail, "Sorry, out of stock");   // Message 2
            return;
        }

        // Message 3: confirm
        _email.Send(customerEmail, $"Order confirmed for {quantity} item(s)");
    }
}
var processor = new OrderProcessor(new EmailService(), new InventoryService());
processor.Place("ada@example.com", 3);    // Email to ada@example.com: Order confirmed for 3 item(s)
processor.Place("ada@example.com", 99);   // Email to ada@example.com: Sorry, out of stock
Tell, do not ask

_inventory.TryReserve(3) is good message passing - the caller states its intent and inventory applies its own rules. Reaching in for data and deciding on its behalf (if (inventory.Stock >= 3) inventory.Stock -= 3;) leaks the rules into the caller and defeats the point of objects.

6. Constructors - object creation

A constructor runs when an object is created. Its job is to leave the object in a valid state - never half-built. It has the same name as the class and no return type.

public class User
{
    public string Email { get; }
    public string DisplayName { get; }
    public DateTime RegisteredUtc { get; }

    // Primary constructor: enforces that a User always has a valid email
    public User(string email, string displayName)
    {
        if (string.IsNullOrWhiteSpace(email))
            throw new ArgumentException("Email is required.", nameof(email));

        Email = email;
        DisplayName = displayName;
        RegisteredUtc = DateTime.UtcNow;
    }

    // Overloaded constructor that delegates to the one above with ": this(...)"
    public User(string email) : this(email, displayName: email.Split('@')[0])
    {
    }
}
var u1 = new User("ada@example.com", "Ada L.");
var u2 = new User("alan@example.com");
Console.WriteLine(u2.DisplayName);   // alan
// var bad = new User("");           // throws ArgumentException

// C# 12 primary constructor - the shortest form
public class Point(int x, int y)
{
    public int X { get; } = x;
    public int Y { get; } = y;
    public double DistanceFromOrigin() => Math.Sqrt(X * X + Y * Y);
}

var p = new Point(3, 4);
Console.WriteLine(p.DistanceFromOrigin());   // 5
Write a constructor once you have required data

Object initialiser syntax (new Car { Make = "Ford" }) is convenient but cannot force a caller to supply anything. If an object is meaningless without a value, take it as a constructor parameter - then it is impossible to create an invalid object.

7. Destructors and cleanup

In C++ a destructor runs at a moment you control. In C# the garbage collector frees memory automatically, at a time nobody can predict. So C# splits cleanup into two very different tools.

Finalizer (the C# "destructor") - rarely what you want

public class LegacyHandleWrapper
{
    ~LegacyHandleWrapper()          // finalizer: same syntax as a C++ destructor
    {
        // Runs on the GC's finalizer thread, at an unpredictable time,
        // and is NOT guaranteed to run at all before the process exits.
        Console.WriteLine("Finalizer ran.");
    }
}

IDisposable - the one you will actually use

For anything that holds a file handle, network socket, or database connection, implement IDisposable and let the caller use using. Cleanup then happens at a precise, predictable point.

public class ReportWriter : IDisposable
{
    private readonly StreamWriter _writer;
    private bool _disposed;

    public ReportWriter(string path)
    {
        _writer = new StreamWriter(path);      // acquire the resource
        Console.WriteLine("File opened.");
    }

    public void WriteLine(string line) => _writer.WriteLine(line);

    public void Dispose()
    {
        if (_disposed) return;                 // safe to call twice
        _writer.Dispose();                     // release the resource
        _disposed = true;
        Console.WriteLine("File closed.");
    }
}
// "using" calls Dispose() automatically at the end of the block,
// even if an exception is thrown inside it.
using (var report = new ReportWriter("report.txt"))
{
    report.WriteLine("Quarterly figures");
}   // "File closed." prints here

// C# 8 shorthand - disposed at the end of the enclosing scope
using var report2 = new ReportWriter("report2.txt");
report2.WriteLine("Another report");

Everything together

One short program using all six building blocks:

using System;
using System.Collections.Generic;

// CLASS: the blueprint
public class Library
{
    // ATTRIBUTES: private field + public properties
    private readonly List<string> _books = new();
    public string Name { get; }
    public int BookCount => _books.Count;      // computed property

    // CONSTRUCTOR: a Library always has a name
    public Library(string name)
    {
        if (string.IsNullOrWhiteSpace(name))
            throw new ArgumentException("Name is required.", nameof(name));
        Name = name;
    }

    // METHODS
    public void Add(string title) => _books.Add(title);

    public bool Has(string title) => _books.Contains(title);
}

public class Member
{
    public string Name { get; }
    public Member(string name) => Name = name;

    // MESSAGE PASSING: this object calls methods on another object
    public void Borrow(Library library, string title)
    {
        if (library.Has(title))
            Console.WriteLine($"{Name} borrowed '{title}' from {library.Name}.");
        else
            Console.WriteLine($"'{title}' is not in {library.Name}.");
    }
}

class Program
{
    static void Main()
    {
        // OBJECTS: two instances of the same blueprint
        var cityLibrary = new Library("City Library");
        cityLibrary.Add("The Pragmatic Programmer");

        var member = new Member("Ada");
        member.Borrow(cityLibrary, "The Pragmatic Programmer");
        member.Borrow(cityLibrary, "Moby Dick");

        Console.WriteLine($"{cityLibrary.Name} holds {cityLibrary.BookCount} book(s).");
    }
}
Ada borrowed 'The Pragmatic Programmer' from City Library.
'Moby Dick' is not in City Library.
City Library holds 1 book(s).
