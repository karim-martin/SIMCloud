Permissions & NSG Rules

Azure

Every Azure RBAC role, resource provider, NSG rule, and policy guardrail this guide depends on - in one place.

Read this before you run a single command

Azure gates a deployment in five places: your Entra ID directory roles, your Azure RBAC role assignments, whether the resource providers are registered on the subscription, what Azure Policy allows, and what the network security groups permit. Contributor on the subscription is not enough to finish this guide - and that surprises almost everyone the first time.

Five Identities, Five Permission Sets

IdentityWhat it isUsed for
OperatorYou, signed in with az loginCreating the resource group, VNet, AKS cluster, and role assignments
CI/CD identityService connection using workload identity federationPushing to ACR and rolling out Deployments
Cluster identityAKS control plane managed identityManaging load balancers, public IPs, and subnets
Kubelet identityNode pool managed identityPulling images from ACR
Workload identityUser-assigned managed identity federated to a Kubernetes service accountRuntime access to Key Vault, Storage, and Azure SQL

1. Register Resource Providers First

Azure does not expose a service in a subscription until its resource provider is registered. This is the equivalent of enabling APIs on GCP, and it is the first thing to fail on a fresh subscription. Registration is idempotent and takes a few minutes.

for RP in \
  Microsoft.ContainerService \
  Microsoft.ContainerRegistry \
  Microsoft.Network \
  Microsoft.Compute \
  Microsoft.Storage \
  Microsoft.Sql \
  Microsoft.KeyVault \
  Microsoft.ManagedIdentity \
  Microsoft.OperationalInsights \
  Microsoft.OperationsManagement \
  Microsoft.Insights \
  Microsoft.Monitor \
  Microsoft.PolicyInsights
do
  az provider register --namespace "$RP"
done

# Watch until every one reports Registered
az provider list \
  --query "[?namespace=='Microsoft.ContainerService' || namespace=='Microsoft.KeyVault' \
            || namespace=='Microsoft.Sql' || namespace=='Microsoft.ContainerRegistry'] \
           .{Provider:namespace, State:registrationState}" \
  --output table
You need permission to register

az provider register requires Microsoft.Resources/subscriptions/providers/register/action, which Contributor holds but a narrowly scoped custom role may not. In a governed subscription this is often done centrally - check with az provider list before assuming you can do it yourself.

2. Operator Roles Required

Contributor cannot create role assignments

Contributor can create almost every resource in this guide but cannot grant access to any of them. The moment you run az aks update --attach-acr, wire up workload identity, or assign a Key Vault role, you need Owner, User Access Administrator, or Role Based Access Control Administrator. Sort this out before you start - it blocks roughly half the guide.

RoleScopeNeeded for
ContributorSubscription or resource groupCreating the resource group, VNet, AKS, SQL, storage, ACR
Role Based Access Control AdministratorResource groupCreating role assignments - narrower than User Access Administrator, prefer it
User Access AdministratorSubscriptionSame, when the assignment scope crosses resource groups
Azure Kubernetes Service Cluster User RoleAKS clusterPulling kubeconfig with az aks get-credentials
Azure Kubernetes Service RBAC Cluster AdminAKS clusterFull kubectl access when Azure RBAC for Kubernetes is enabled
Network ContributorVNet or subnetRequired when AKS uses a VNet in a different resource group
AcrPushContainer registryPushing images from your workstation
Key Vault AdministratorKey vaultCreating secrets when the vault uses RBAC rather than access policies
DNS Zone ContributorDNS zoneRecords for your custom domain
Managed Identity OperatorManaged identityAssigning a user-assigned identity to AKS or AGIC
Application Developer (Entra ID)DirectoryOnly if you create app registrations instead of managed identities
 
export SUB_ID=$(az account show --query id -o tsv)
export RG="myapp-rg"
export OPERATOR_OID=$(az ad signed-in-user show --query id -o tsv)

az role assignment create \
  --assignee-object-id "$OPERATOR_OID" --assignee-principal-type User \
  --role "Contributor" \
  --scope "/subscriptions/$SUB_ID/resourceGroups/$RG"

az role assignment create \
  --assignee-object-id "$OPERATOR_OID" --assignee-principal-type User \
  --role "Role Based Access Control Administrator" \
  --scope "/subscriptions/$SUB_ID/resourceGroups/$RG"

Check What You Actually Have

# Every role assigned to you, including inherited ones
az role assignment list --assignee "$OPERATOR_OID" --all --include-inherited \
  --query "[].{Role:roleDefinitionName, Scope:scope}" --output table

# Confirm you can create role assignments at all
az role assignment list --assignee "$OPERATOR_OID" --all \
  --query "[?roleDefinitionName=='Owner' \
            || roleDefinitionName=='User Access Administrator' \
            || roleDefinitionName=='Role Based Access Control Administrator']" \
  --output table

3. Cluster and Workload Identity Permissions

AKS runs on managed identities. Each one needs specific grants, and three of them are common failure points.

IdentityRoleScopeSymptom if missing
Cluster (control plane)Network ContributorCustom VNet or subnetCluster creation fails, or LoadBalancer services never get an IP
ContributorNode resource group (MC_*)Assigned automatically - do not remove it
KubeletAcrPullContainer registryImagePullBackOff with 401 Unauthorized
AGICContributorApplication gatewayIngress objects never reach the gateway
ReaderGateway resource groupAGIC pod crash-loops on startup
Network ContributorGateway subnetGateway cannot bind to the subnet
Workload (application)Key Vault Secrets UserKey vaultSecret mount fails, pod stuck in ContainerCreating
Storage Blob Data ContributorStorage accountFile uploads return 403
Entra admin on the SQL serverAzure SQLLogin fails for the managed identity

Attach ACR

# The convenience command - it creates an AcrPull role assignment for you,
# which is why it needs Owner or User Access Administrator
az aks update --name myapp-aks --resource-group "$RG" --attach-acr myappacr

# The explicit equivalent, usable with only RBAC Administrator
KUBELET_OID=$(az aks show -n myapp-aks -g "$RG" \
  --query identityProfile.kubeletidentity.objectId -o tsv)
ACR_ID=$(az acr show -n myappacr --query id -o tsv)

az role assignment create \
  --assignee-object-id "$KUBELET_OID" --assignee-principal-type ServicePrincipal \
  --role AcrPull --scope "$ACR_ID"

Custom VNet

The bring-your-own-VNet trap

AKS creating its own VNet works out of the box. Point it at a VNet you already own - the usual pattern in an enterprise - and the cluster identity has no rights over that subnet. Creation may still succeed, then the first LoadBalancer service sits at <pending> forever with nothing useful in the events. Grant Network Contributor on the subnet before creating the cluster.

SUBNET_ID=$(az network vnet subnet show \
  -g "$RG" --vnet-name myapp-vnet -n aks-nodes --query id -o tsv)

CLUSTER_OID=$(az aks show -n myapp-aks -g "$RG" \
  --query identity.principalId -o tsv)

az role assignment create \
  --assignee-object-id "$CLUSTER_OID" --assignee-principal-type ServicePrincipal \
  --role "Network Contributor" --scope "$SUBNET_ID"

Workload Identity Federation

# User-assigned identity for the application
az identity create --name myapp-workload-id --resource-group "$RG"

IDENTITY_CLIENT_ID=$(az identity show -n myapp-workload-id -g "$RG" \
  --query clientId -o tsv)
OIDC_ISSUER=$(az aks show -n myapp-aks -g "$RG" \
  --query oidcIssuerProfile.issuerUrl -o tsv)

# Federate it to the Kubernetes service account - subject must match exactly
az identity federated-credential create \
  --name myapp-federated \
  --identity-name myapp-workload-id \
  --resource-group "$RG" \
  --issuer "$OIDC_ISSUER" \
  --subject "system:serviceaccount:app:app-sa" \
  --audience api://AzureADTokenExchange

# Grant it what it needs at runtime
az role assignment create \
  --assignee "$IDENTITY_CLIENT_ID" \
  --role "Key Vault Secrets User" \
  --scope "$(az keyvault show -n myapp-kv --query id -o tsv)"
The subject string is unforgiving

system:serviceaccount:NAMESPACE:SERVICEACCOUNT must match the pod's actual service account character for character. A namespace typo produces AADSTS70021: No matching federated identity record found and nothing more specific. Confirm the OIDC issuer is enabled with --enable-oidc-issuer --enable-workload-identity.

4. Who Can Run kubectl

AKS offers three authorization models. Pick one deliberately - mixing them causes confusing partial access.

ModelHow access is grantedUse when
Local accountsaz aks get-credentials --admin returns a certificateNever in production - disable with --disable-local-accounts
Entra ID + Kubernetes RBACEntra group mapped to a ClusterRoleBinding by group object IDYou want Kubernetes-native RBAC with Entra sign-in
Entra ID + Azure RBACAzure role assignments on the cluster resourceRecommended - access is visible and auditable in Azure
 
# Enable Entra integration with Azure RBAC for Kubernetes authorization
az aks update --name myapp-aks --resource-group "$RG" \
  --enable-azure-rbac --enable-aad --disable-local-accounts

CLUSTER_ID=$(az aks show -n myapp-aks -g "$RG" --query id -o tsv)

# Platform engineers - full cluster admin
az role assignment create \
  --assignee "platform-team@example.com" \
  --role "Azure Kubernetes Service RBAC Cluster Admin" \
  --scope "$CLUSTER_ID"

# CI/CD - write access to one namespace only
az role assignment create \
  --assignee "$PIPELINE_CLIENT_ID" \
  --role "Azure Kubernetes Service RBAC Writer" \
  --scope "$CLUSTER_ID/namespaces/app"

# Everyone still needs Cluster User Role just to download kubeconfig
az role assignment create \
  --assignee "developers@example.com" \
  --role "Azure Kubernetes Service Cluster User Role" \
  --scope "$CLUSTER_ID"
az aks get-credentials --name myapp-aks --resource-group "$RG"
kubectl auth can-i --list --namespace app

Private Clusters

# A private cluster has no public API endpoint at all
az aks create ... --enable-private-cluster

# Or keep the public endpoint and restrict it by source IP
az aks update --name myapp-aks --resource-group "$RG" \
  --api-server-authorized-ip-ranges 203.0.113.10/32,198.51.100.0/24

# Run a command inside a private cluster without a jumpbox or VPN
az aks command invoke --name myapp-aks --resource-group "$RG" \
  --command "kubectl get pods -n app"

5. Network Security Group Rules

NSGs attach to subnets or NICs and are evaluated by priority, lowest number first. AKS manages the rules it needs on the load balancer, but rules you add to the node subnet can still break the cluster.

Application Gateway Subnet

Ports 65200-65535 are not optional

Application Gateway v2 receives its health and configuration traffic from the GatewayManager service tag on ports 65200-65535. Block them and the gateway reports an unhealthy backend or fails provisioning entirely, with an error that says nothing about NSGs. The gateway subnet must also be dedicated - no other resource may share it.

PriorityDirectionSourcePortActionPurpose
100InboundGatewayManager65200-65535AllowGateway v2 control plane - mandatory
110InboundAzureLoadBalancerAnyAllowHealth probes
120InboundInternet443AllowPublic HTTPS
130InboundInternet80AllowHTTP, redirected to HTTPS
4000InboundInternetAnyDenyCatch-all
100OutboundAKS node subnet80, 443, 30000-32767AllowForward to backend pods

AKS Node Subnet

PriorityDirectionSource or destinationPortActionPurpose
100InboundApp Gateway subnet 10.0.2.0/2480, 443, 30000-32767AllowIngress traffic to pods
110InboundAzureLoadBalancerAnyAllowHealth probes - required
120InboundVirtualNetworkAnyAllowNode-to-node and pod-to-pod
4000InboundInternetAnyDenyNodes are never directly reachable
100OutboundAzureCloud443AllowControl plane, ACR, Key Vault, Monitor
110OutboundDatabase subnet1433AllowAzure SQL
120OutboundInternet123 (UDP)AllowNTP - clock skew breaks token validation

Database Subnet

PriorityDirectionSourcePortActionPurpose
100InboundAKS node subnet 10.0.1.0/241433AllowApplication to database
4000InboundAnyAnyDenyNothing else reaches the database
 
# Application Gateway subnet NSG
az network nsg create --name agw-nsg --resource-group "$RG"

az network nsg rule create --nsg-name agw-nsg --resource-group "$RG" \
  --name allow-gateway-manager --priority 100 \
  --direction Inbound --access Allow --protocol Tcp \
  --source-address-prefixes GatewayManager \
  --destination-port-ranges 65200-65535 \
  --description "Application Gateway v2 control plane - required"

az network nsg rule create --nsg-name agw-nsg --resource-group "$RG" \
  --name allow-lb-probes --priority 110 \
  --direction Inbound --access Allow --protocol "*" \
  --source-address-prefixes AzureLoadBalancer \
  --destination-port-ranges "*"

az network nsg rule create --nsg-name agw-nsg --resource-group "$RG" \
  --name allow-https --priority 120 \
  --direction Inbound --access Allow --protocol Tcp \
  --source-address-prefixes Internet --destination-port-ranges 443

az network nsg rule create --nsg-name agw-nsg --resource-group "$RG" \
  --name deny-all-inbound --priority 4000 \
  --direction Inbound --access Deny --protocol "*" \
  --source-address-prefixes Internet --destination-port-ranges "*"

az network vnet subnet update --resource-group "$RG" \
  --vnet-name myapp-vnet --name app-gateway --network-security-group agw-nsg
# Database subnet NSG - reachable from the node subnet only
az network nsg create --name db-nsg --resource-group "$RG"

az network nsg rule create --nsg-name db-nsg --resource-group "$RG" \
  --name allow-sql-from-aks --priority 100 \
  --direction Inbound --access Allow --protocol Tcp \
  --source-address-prefixes 10.0.1.0/24 --destination-port-ranges 1433

az network nsg rule create --nsg-name db-nsg --resource-group "$RG" \
  --name deny-all-inbound --priority 4000 \
  --direction Inbound --access Deny --protocol "*" \
  --source-address-prefixes "*" --destination-port-ranges "*"

az network vnet subnet update --resource-group "$RG" \
  --vnet-name myapp-vnet --name database --network-security-group db-nsg

6. Azure SQL Firewall

Azure SQL enforces its own firewall on top of the NSG. Three access models, in increasing order of safety.

ModelHow it worksVerdict
Server firewall rulesAllowlist of public IP rangesAcceptable for an admin workstation, never for the application path
Allow Azure services0.0.0.0 pseudo-ruleOpens the server to every Azure tenant - do not use it
Private endpointPrivate IP in your VNet, public access disabledUse this - the guide's target state
 
# Turn off public access and use a private endpoint
az sql server update --name myapp-sql --resource-group "$RG" \
  --enable-public-network false

az network private-endpoint create \
  --name myapp-sql-pe --resource-group "$RG" \
  --vnet-name myapp-vnet --subnet database \
  --private-connection-resource-id "$(az sql server show -n myapp-sql -g "$RG" --query id -o tsv)" \
  --group-id sqlServer \
  --connection-name myapp-sql-conn

# Private DNS so the server FQDN resolves to the private IP
az network private-dns zone create -g "$RG" -n "privatelink.database.windows.net"
az network private-dns link vnet create -g "$RG" \
  --zone-name "privatelink.database.windows.net" \
  --name sql-dns-link --virtual-network myapp-vnet --registration-enabled false

# Verify no broad firewall rules were left behind
az sql server firewall-rule list --server myapp-sql --resource-group "$RG" --output table
Check for the 0.0.0.0 rule

A firewall rule with start and end IP both 0.0.0.0 is the "Allow Azure services" toggle. It permits connections from any Azure resource in any subscription belonging to any customer. Portal wizards enable it by default. Delete it.

# Azure Firewall ships an FQDN tag that covers the AKS requirements
az network firewall application-rule create \
  --firewall-name myapp-fw --resource-group "$RG" \
  --collection-name aks-egress --name allow-aks \
  --source-addresses 10.0.1.0/24 \
  --fqdn-tags AzureKubernetesService \
  --action Allow --priority 100

8. Pod-Level Network Policy

# Network policy must be chosen at cluster creation - it cannot be added later
az aks create ... --network-plugin azure --network-policy calico
# k8s/security/default-deny.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-ingress
  namespace: app
spec:
  podSelector: {}
  policyTypes: [Ingress]
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-frontend-to-api
  namespace: app
spec:
  podSelector:
    matchLabels: { app: dotnet-api }
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector:
            matchLabels: { app: react-frontend }
      ports:
        - protocol: TCP
          port: 8080

9. Azure Policy Guardrails

Azure Policy is evaluated at deployment time and overrides RBAC. A deny effect blocks the request no matter what roles you hold.

Common policyEffect on this guideHow to proceed
Allowed locationsResource creation denied outside approved regionsSet your region to an approved one before starting
Deny public network access on PaaSAzure SQL and Storage must use private endpointsAlready compatible - the guide targets private endpoints
Require NSG on every subnetSubnet creation fails without an NSG attachedCreate the NSG in the same Terraform apply as the subnet
Deny public IP addressesStandard load balancer cannot get a public IPUse an internal load balancer behind Application Gateway or Front Door
Require customer-managed keysStorage and disks must use your own keyProvision the key vault key before the storage account
Enforce required tagsUntagged resources deniedSet tags in the Terraform provider defaults
AKS policy add-on (Gatekeeper)Privileged pods, host networking, and latest tags rejectedSet securityContext and pin image tags in your manifests
 
# What is assigned to this subscription
az policy assignment list --output table

# What has already been flagged non-compliant
az policy state summarize --resource-group "$RG"

# Enable the AKS policy add-on
az aks enable-addons --addons azure-policy --name myapp-aks --resource-group "$RG"

10. Pre-Flight Verification

#!/usr/bin/env bash
set -euo pipefail
RG="${RG:-myapp-rg}"
CLUSTER="${CLUSTER:-myapp-aks}"

echo "== Subscription =="
az account show --query "{Name:name, Id:id, Tenant:tenantId}" --output table

echo "== Resource providers =="
az provider list \
  --query "[?namespace=='Microsoft.ContainerService' || namespace=='Microsoft.Network' \
            || namespace=='Microsoft.Sql' || namespace=='Microsoft.KeyVault' \
            || namespace=='Microsoft.ContainerRegistry' \
            || namespace=='Microsoft.ManagedIdentity'] \
           .{Provider:namespace, State:registrationState}" --output table

echo "== My role assignments =="
OID=$(az ad signed-in-user show --query id -o tsv)
az role assignment list --assignee "$OID" --all --include-inherited \
  --query "[].{Role:roleDefinitionName, Scope:scope}" --output table

echo "== Can I create role assignments? =="
az role assignment list --assignee "$OID" --all \
  --query "[?roleDefinitionName=='Owner' || roleDefinitionName=='User Access Administrator' \
            || roleDefinitionName=='Role Based Access Control Administrator'] | length(@)"

echo "== Policy assignments that could block me =="
az policy assignment list --query "[].{Name:displayName, Scope:scope}" --output table

echo "== NSG rules =="
for NSG in $(az network nsg list -g "$RG" --query "[].name" -o tsv); do
  echo "--- $NSG ---"
  az network nsg rule list -g "$RG" --nsg-name "$NSG" \
    --query "[].{P:priority,Dir:direction,Access:access,Src:sourceAddressPrefix,Port:destinationPortRange}" \
    --output table
done

echo "== Azure SQL firewall rules (0.0.0.0 means 'all Azure services') =="
az sql server firewall-rule list --server myapp-sql -g "$RG" --output table 2>/dev/null || true
